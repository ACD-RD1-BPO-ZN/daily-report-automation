# 🤖 互動發放 (Reaction Airdrop) 功能指南

這份文件記錄了 Discord 機器人 `!互動發放` 與 `!測試互動發放` 指令的核心邏輯、操作方式與相關注意事項，提供管理員與未來開發維護時的參考。

## 1. 功能概述
`!互動發放` 是一項自動化虛擬金幣（Z 幣）發放工具。它能讀取指定歷史訊息底下的「所有表情符號 (Emoji) 互動紀錄」，並自動發送 UnbelievaBoat API 獎勵給所有參與互動的玩家。

**核心特色：**
- **自動去重複 (Deduplication)**：使用 `set()` 集合機制，即使同一位玩家點擊了多種不同的表情符號，也只會被記錄一次、發放一次獎勵，避免重複派彩。
- **過濾機器人 (Bot Filtering)**：程式會自動略過機器人帳號（如自身或其他 Bot）的互動。
- **後台遙控與廣播隔離**：管理員能在隱密的專屬頻道（如 `#後台中心`）輸入指令發動派發，機器人讀取完畢後，只會將精美的「結算公告面板」投射到正式頻道（避免管理指令外洩）。

---

## 2. 指令使用語法

```text
!互動發放 <訊息ID> <單人發放金額> <發放原因或感謝詞>
```

**範例：**
```text
!互動發放 1488160326599053413 50 感謝大家參與「自定義內容標籤」意見調查！
```

* **測試環境專用指令**：若想在正式發放前進行演練，請使用 `!測試互動發放`（語法完全相同）。機器人會將結算面板發送到 `TEST_CHANNEL_ID` 指定的測試頻道，面板會呈現灰色，且標記對象將切換為 `TEST_MENTION`。

## 3. ⚠️ 重要注意事項

### 3.1 訊息搜尋範圍 (Message Fetching Scope)
當前的設計機制，機器人尋找目標 `<訊息ID>` 的範圍僅限於以下兩個頻道：
1. **指令發動的當下頻道**（例如管理員正在輸入指令的 `#後台中心`）。
2. **正式廣播頻道**（`.env` 檔案內所設定的 `TARGET_CHANNEL_ID`）。

**限制提醒**：
如果您將問卷發布在**其他未指定的頻道**（例如 `#大廳` 或 `#活動公告`），並試圖在 `#後台中心` 遙控發放，機器人將無法跨頻道尋找到該篇文章，並會回報 `❌ 找不到指定的訊息`。
- **解決方案**：遇到此情況，請直接在「發布該問卷的頻道」內輸入發放指令即可。

### 3.2 第三方 API 速率限制 (Rate Limit)
在向 UnbelievaBoat 伺服器發送金幣 PATCH 請求時，我們設定了嚴格的保護機制：
- 在迴圈解析每一個使用者的派發流程中，強制加上了 `await asyncio.sleep(0.2)`（即每秒最多處理 5 人）。
- 這是為了避免瞬間發送大量 Request 導致機器人觸發 Discord 或 UB 的 API 速率限制（Rate Limit 429 Error）而遭到封鎖。未來若人數增長，請**不要刪除**這段睡眠語法。

### 3.3 Discord 面板字元限制 (Embed Field Limit)
Discord API 對 Embed 面板中的欄位有嚴格的 1024 字元長度限制。
- 我們實作了**截斷機制**（`[:1020] + "..."`）：當單次參與人數過多，導致「成功發放名單（`@user1 @user2...`）」串聯字串過長時，程式會自動裁切並加上刪節號，以確保公告能順利發送而不會發生例外錯誤 (Exception)。
